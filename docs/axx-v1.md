# AxCrypt 1.x 복호화

공개 포맷 문서를 바탕으로 Rust에서 독립 구현했다. AxCrypt의 소스 코드나 실행 파일을 포함하지 않는다. ESB 포맷과 암호화 동작은 변경하지 않는다.

## 사용법

GUI에서 복호화 또는 검증을 선택하고 `.axx` 파일을 지정한다. 비밀번호 입력 후 백그라운드에서 전체 암호문을 인증한다. 복호화는 이어서 저장 대화상자에 인증된 원본 파일명을 표시한다. 이름과 위치를 바꿀 수 있으며 기존 파일은 덮어쓰지 않는다. 검증은 출력 파일을 만들지 않는다. 진행 중 취소를 지원한다.

확장자 대신 파일 GUID로 판별한다. CLI에서도 `withcrypt decrypt old.axx --output restored` 및 `withcrypt verify old.axx`를 지원한다. 탐색기 복호화 메뉴는 저장 대화상자 없이 원본 폴더에 인증된 원본 파일명으로 복원한다.

## 현재 지원 범위

- 파일 형식 3.0~3.2의 AxCrypt 1.x 파일. 제공한 샘플의 형식 3.2를 실제 검증했다. 다른 생성기 버전은 추가 샘플 검증이 필요하다.
- 비밀번호만 사용한 파일과 ASCII 비밀번호. 한글 등 비 ASCII 비밀번호는 과거 Windows 코드 페이지에 따라 바이트가 달라지므로 명시적으로 거부한다.
- AES-128 복호화, 파일 무결성 검증, zlib 압축 해제, UTF-16LE 원본 파일명 복원.
- Unicode 이름 헤더가 없는 경우 ASCII 이름만 지원한다.
- 암호화, 키 파일 및 자체 복호화 EXE는 제공하지 않는다. AxCrypt 2.x 지원은 [별도 문서](axx-v2.md)를 참고한다.

## 처리와 제한

키 래핑을 해제한 뒤, 전체 암호문을 검증하고 파일명을 해석한다. 복호화는 두 번째 읽기에서 고정 크기 버퍼로 수행한다. 압축 해제 결과는 인증된 원본 크기를 넘을 수 없다. 출력은 기존 파일 트랜잭션을 재사용하며 실패·취소 시 삭제한다. 원본 파일 변경도 검사한다.

헤더는 합계 1 MiB, 최대 256개로 제한하고 키 래핑 반복은 최대 1,000,000회로 제한한다. 이보다 큰 반복값의 파일은 자원 소모 방지를 위해 명시적으로 거부한다. 전체 HMAC 확인을 위해 암호문을 먼저 한 번 읽으므로 ESB보다 읽기 횟수가 늘어난다.

AxCrypt의 레거시 암호 구성은 복호화 호환성만을 위한 것이다. ESB 신규 암호화의 Argon2id 및 AEAD 설정에 영향을 주지 않는다.

## 검증

`tests/fixtures/axcrypt-v1/`에는 사용자가 제공한 `.axx` 샘플 6개와 대응 원본을 저장했다. 테스트 비밀번호는 `1111`이다. 빈 파일, 비압축 텍스트, 압축 텍스트, 한글 파일명, JPEG 및 ZIP을 복호화한 결과가 원본과 바이트 단위로 일치한다.

잘못된 비밀번호, 헤더·본문 변조, 모든 위치에서의 잘림, 뒤에 붙인 데이터, 반복 횟수 제한, 기존 출력 보존, 취소 및 미완성 출력 정리를 검사한다. GUI 백그라운드 작업 테스트로 6개 샘플의 복원·이름 변경·검증·잘못된 비밀번호 오류를 확인했다. 쉘 모드에서는 저장 대화상자 없이 원본 폴더에 복원하고 기존 출력을 보존하는 동작을 검사했다. Windows/Linux 실제 실행은 아직 검증하지 않았다.
