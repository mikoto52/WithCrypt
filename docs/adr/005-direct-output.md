# ADR-005: 대상 파일에 직접 쓰기

날짜: 2026-10-03. ADR-001의 "임시 디렉터리 + hard_link 게시" 결정을 대체한다.

## 배경

기존 파일 트랜잭션은 출력 폴더 안에 `.withcrypt-*` 임시 디렉터리를 만들고 거기에 결과를 쓴 뒤 `hard_link`로 최종 이름을 붙였다. 데이터 복사는 없었지만 임시 디렉터리, `whoami.exe`/`icacls.exe` 실행, 하드링크 지원 볼륨이 필요했다. 사용자는 대상 폴더에 바로 쓰는 단순한 구조를 선택했다.

## 결정

`files::output_transaction`은 최종 경로를 `create_new`로 배타 생성하고 그 파일에 바로 쓴다.

- `create_new`는 원자적 no-clobber 생성이다. 이미 있는 파일, 심볼릭 링크, 입력의 하드링크 별칭을 덮어쓰지 않고 `OutputExists`로 실패한다. Unix는 생성 시 0600이다. Windows는 생성 직후, 내용을 쓰기 전에 현재 사용자 SID만 접근하도록 파일 ACL을 제한하고 실패하면 빈 파일을 지우고 중단한다.
- 처리, 입력 변경 검사, flush/sync, `Committing` 알림, 다시 입력 변경 검사가 모두 끝나야 성공이다. 마지막에 경로가 여전히 이 작업이 만든 파일인지 파일 ID로 확인하고, 아니면 `OutputChanged`로 실패한다.
- 실패·취소·인증 실패 때는 경로가 여전히 이 작업이 만든 파일일 때만 삭제한다. 다른 프로세스가 바꿔 놓은 파일은 지우지 않는다. 삭제 실패는 `Cleanup` 오류로 원래 오류와 함께 보고한다.
- 성공 후의 취소는 저장된 파일을 지우지 않는다. Unix는 디렉터리도 fsync한다.

## 결과

- 하드링크가 필요 없어져 FAT/exFAT 같은 볼륨에서도 동작한다. 임시 디렉터리가 사라진다.
- **복호화 중에는 청크 단위로 인증된 평문이 최종 파일 이름으로 보인다.** FINAL·HMAC·EOF 검증 전에는 잘림 여부가 확정되지 않은 결과다. 다른 프로그램이 이 시점에 파일을 열 수 있다. 실패하면 삭제하지만, 프로세스가 강제 종료되거나 시스템이 멈추면 미완성 평문이 원래 이름으로 남을 수 있다. 사용자는 "완료" 표시 전의 파일을 신뢰하지 않아야 한다.
- 암호화 결과는 암호문이므로 같은 상황에서 남는 것은 검증에 실패하는 미완성 `.esb`다.
- 저수준 스트림 API의 "검증 전 출력 격리는 호출자 책임" 원칙은 그대로다. 파일 API는 격리 대신 실패 시 삭제로 처리한다.
