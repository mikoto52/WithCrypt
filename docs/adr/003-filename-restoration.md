# ADR-003: 암호화된 원본 파일명과 저장 대상 선택

사용자 요구에 따라 원래 파일명을 복호화 결과의 기본 이름으로 사용한다. 기존 ESB v1에는 이미 첫 번째 암호화 레코드 META에 확장자를 포함한 basename이 있다. 따라서 공개 H(64바이트)와 META를 논리적인 헤더로 사용하고, v1 바이너리 구조·KDF·암호화 벡터는 유지한다. 원본 절대 경로는 저장하지 않는다.

CLI encrypt의 --output은 생략할 수 있으며 입력 파일명 전체에 .esb를 덧붙인다. decrypt의 --output은 필수 기존 디렉터리로 의미가 바뀐다. META를 인증하고 안전한 basename인지 검사한 뒤 해당 디렉터리에 결합한다. 경로 구분자, 제어 문자, Windows 금지 문자·예약 이름 및 끝 공백·마침표를 거부한다. 기존 출력과 원본은 덮어쓰지 않는다.

GUI는 출력 경로 입력란을 없애고 시작 시 저장 대화상자를 사용한다. 복호화는 백그라운드에서 비밀번호로 META를 먼저 인증하여 원래 이름을 얻는다. 이 시점은 전체 파일 검증 성공이 아니다. 같은 열린 입력 핸들과 파생 키를 PreparedDecryption에 보관하고 사용자가 이름·위치를 선택하면 본문 처리를 이어간다. KDF는 한 번만 실행한다. 대화상자를 취소하면 준비 상태를 버리며 출력 파일은 생성하지 않는다. 선택 대기 중 입력 변경을 검사하고, 전체 인증·HMAC·EOF·동기화 후에만 결과를 확정한다.

UTF-8로 표현할 수 없거나 이식 가능한 basename 제약을 만족하지 않는 원본 이름은 기존 정책대로 빈 이름으로 저장하고 알린다. 이름이 없는 기존 ESB도 읽을 수 있다. CLI는 자동 복원 이름을 추측하지 않고 종료 코드 2로 GUI 사용을 안내한다. GUI는 decrypted.bin을 기본값으로 제시하고 사용자가 이름을 지정한다.

호환성: 기존 정상 v1 파일과 고정 벡터는 그대로 읽는다. CLI decrypt의 --output은 파일 경로에서 디렉터리로 바뀌므로 기존 스크립트를 수정해야 한다. 파일명 검증은 자동 복원을 위해 강화되어 예전 독자가 허용했던 일부 비이식적 META 이름은 거부될 수 있다. 저수준 스트림 및 명시적 파일 목적지 API는 유지한다.
